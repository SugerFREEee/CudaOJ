
## 取矩阵


```cpp
// input[M,K]
// 从input[r0, r0+BM][c0, c0+BK]读取数据到shared memory tile
__shared__ float tile[BM][BK];

int tid = threadIdx.x + threadIdx.y*blockDim.x;
int stride = blockDim.x*blockDim.y;

for(int i = tid;i< BM*BK;i+=stride){
    int r = i/BK;
    int c = i%BK;
    int gr = r + r0;
    int gc = c + c0;
    tile[r][c] = (gr<M && gc<K) ? 从input[gr*K+gc] : 0.0f;
}
__syncthreads();

```

## 矩阵乘法

```
A[BM][BK]
B[BK][BN]
out[M][N]
输出到out[r0, r0+BM][c0, c0+BN]
```

### 朴素版（每个线程负责1个元素）

```cpp
// block[BM, BN]

float acc = 0.0f;
// 每个线程负责threadIdx.y行和threadIdx.x列计算
for (int h = 0; h < BK; ++h) {
    acc += A[threadIdx.y][h] * B[h][threadIdx.x];
}
int row = r0 + threadIdx.y;
int col = c0 + threadIdx.x;
if (row < M && col < K) {
    C[row * K + col] = acc;
}
```


### 每个线程负责 Tm×Tn 个输出元素（block级复用）

```cpp
// BLOCK_SIZE：block 的线程总数 小于 BM * BN

// 比如 BM=BN=128, BLOCK_SIZE=256
// 这样1个线程就要负责（BM * BN / BLOCK_SIZE）个元素的计算


// BLOCK_SIZE个线程被逻辑排成[BLOCK_Y, BLOCK_X]的矩阵
// 比如 BLOCK_SIZE=256, BLOCK_X=16, BLOCK_Y=16，那么所有线程被逻辑排成[16][16]的矩阵
// 此时该线程在逻辑矩阵的坐标为
int thread_x = tid % BLOCK_X
int thread_y = tid / BLOCK_X


// 这样每个线程负责 Tm×Tn 个输出元素
// 这些元素按 BLOCK_Y/BLOCK_X 步长分布
// 这样相邻线程能够访问相邻的A，B元素
constexpr int Tm = BM / BLOCK_Y;
constexpr int Tn = BN / BLOCK_X;
float Ct[Tm][Tn] = {0.0f};


// 外层遍历归约BK维度
for (int p = 0; p < BK; p++) {
    for (int i = 0; i < Tm; i++) {
        int row = thread_y + i * BLOCK_Y;
        //一次从 A 取的 A[row][p]，可以复用乘 Tn次
        for (int j = 0; j < Tn; j++) {
            int col = thread_x + j * BLOCK_X;
            Ct[i][j] += A[row][p] * B[p][col];
        }
    }
}

for (int i = 0; i < Tm; i++) {
    int r = r0 + thread_y + i * BLOCK_Y;
    for (int j = 0; j < Tn; j++) {
        int c = c0 + thread_x + j * BLOCK_X;
        if (r < M && c < N) out[r * N + c] = Ct[i][j];
    }
}

```
FMA 是 Fused Multiply-Add，比如`Ct = Ct + A * B`,GPU 上通常有专门的 FMA 指令，一条指令完成乘法和加法。`Ct[i][j] += As[row][p] * Bs[p][col];`就是做一次 FMA。
MIO Throttle Stall 指的是MIO 管线太忙，线程发不出下一条指令，只能等。

这一版虽然已经让每个线程算 8x8 个输出，但 shared memory 的读取仍然写在 FMA 语句里。编译器可能会帮你缓存到寄存器，但代码层面没有明确表达。
如果 shared memory 访问过于频繁，GPU 会出现 MIO Throttle Stall，也就是 shared memory / 数据移动管线成为瓶颈。



### 每个线程负责 Tm×Tn 个输出元素（thread级复用）

```cpp
int thread_x = tid % BLOCK_X
int thread_y = tid / BLOCK_X

constexpr int Tm = BM / BLOCK_Y;
constexpr int Tn = BN / BLOCK_X;
float Ct[Tm][Tn] = {0.0f};


float At[Tm] = {0.0f};
float Bt[Tn] = {0.0f};


for (int p = 0; p < BK; p++) {
    for (int i = 0; i < Tm; i++) {
        int row = thread_y + i * BLOCK_Y;
        At[i] = A[row][p];   // 从 shared 读一次，放到寄存器
    }

    for (int j = 0; j < Tn; j++) {
        int col = thread_x + j * BLOCK_X;
        Bt[j] = B[p][col];   // 从 shared 读一次，放到寄存器
    }

    for (int i = 0; i < Tm; i++) {
        for (int j = 0; j < TN; j++) {
            Ct[i][j] += At[i] * Bt[j];
        }
    }
}

// 下面一样
for (int i = 0; i < Tm; i++) {
    int r = r0 + thread_y + i * BLOCK_Y;
    for (int j = 0; j < Tn; j++) {
        int c = c0 + thread_x + j * BLOCK_X;
        if (r < M && c < N) out[r * N + c] = Ct[i][j];
    }
}
```

### 每个线程负责 Tm×Tn 个输出元素（Warp 级分块优化）

上个例子中，可以证明，当Tm=Tn时，计算访存比最大。
比如 BLOCK_SIZE=256, BLOCK_X=BLOCK_Y=16，时计算访存比最大。
可是，这[16,16]个元素该如何被**划分**给不同warp的不同thread计算呢？
假设 warp 在 M 方向处理有 x 个元素、N 方向处理 y 个元素（xy=32），可以证明x与y越接近，计算访存比最大。32的最接近的公因数即是 4，8。

所以每个 warp 内 32 个 lane 处理 [4,8] 列的元素块是一种计算访存比最大的选择。
假设8 个 warp 在 block tile 中处理排成 4 行 x 2 列的[4,8]元素块。

注意，前面的例子中：
```cpp
int thread_x = tid % BLOCK_X;
int thread_y = tid / BLOCK_X;
```
实际上就是按照[2,16]来划分warp了，这样的话为了warp中相邻线程能读取相邻元素
```cpp
// 每次
int row = thread_y + i * BLOCK_Y;
int col = thread_x + j * BLOCK_X;
```
是跨步读。

但是我们这里划分warp之后，一个warp负责[4,8]个相邻的元素
